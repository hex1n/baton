# Architecture: root-readme-bilingual

**主题**: 根目录 README 双语入口
**状态**: `approved`
**规模**: `Small`

## 1. 问题

需要给项目根目录提供正式的中英双版 README，同时保留英文 README 作为默认入口。

## 2. 第一性原理拆解

### 2.1 问题陈述

问题本质是“如何让根目录文档入口同时服务英文和中文读者”，而不是“是否把整个仓库所有文档都翻译一遍”。

### 2.2 约束

- GitHub 默认入口仍是 `README.md`
- 中文版本应足够正式，不能只是零散中文分析文档替代品
- 维护成本要低，避免引入复杂自动同步机制

### 2.3 方案类别

- 方案 A: 把 `README.md` 写成一份中英混排的大文档
- 方案 B: 保持 `README.md` 英文，新增 `README.zh-CN.md` 中文版
- 方案 C: 把 `README.md` 改成中文，英文版单独放 `README.en.md`

### 2.4 评估

- 为什么方案 B 胜出:
  - 保持 GitHub 默认入口兼容英文读者
  - 中文用户仍可通过顶层显式链接快速进入中文版
  - 维护成本最低，结构最清晰
- 为什么拒绝方案 A:
  - 单文件过长，可读性差，后续维护容易失衡
- 为什么拒绝方案 C:
  - 会改变当前默认对外展示入口，不如 B 稳

## 3. 推荐架构

- 方法:
  - 保留 `README.md` 为英文主入口
  - 新增 `README.zh-CN.md`
  - 两份 README 顶部增加双向语言链接
- 关键变更点:
  - `README.md`
  - `README.zh-CN.md`
- 数据 / 控制边界:
  - 仅影响项目根目录文档入口，不影响 spec 与 bootstrap 行为
- 向后兼容说明:
  - 现有 `README.md` 路径保持不变

## 4. 影响面扫描

| 文件 | 层级 | 处理方式 | 原因 |
|---|---|---|---|
| `README.md` | L1 | modify | 补语言切换和对齐内容 |
| `README.zh-CN.md` | L1 | add | 新增正式中文版本 |

## 5. 验证策略

- 主要检查:
  - 根目录文件列表包含两份 README
  - 双向链接存在
  - 关键主题在两份 README 中都能命中
- 评审重点:
  - 中文版是否准确表达当前 install/update 分发模型
- 验证无法完全消除的风险:
  - 中英两份 README 后续需要人工保持同步

## 6. 风险

- 后续若只改英文 README，中文版本可能滞后

## 7. 自我质疑

1. 这是最优方案类别，还是只是第一个可行方案?
   - 对当前根目录入口需求，这是最稳妥的方案类别。
2. 还有哪些假设尚未验证?
   - 未验证未来是否还需要 `README.ja.md` 等更多语言。
3. 一个怀疑者会先质疑什么?
   - 双文档是否会漂移；当前接受这一维护成本，先解决入口问题。
