# Retrospective: root-readme-bilingual

## 1. 结果

- 关闭状态: `complete`
- 主要阻塞: 无功能性阻塞；仅存在双语 README 后续需要人工保持同步的维护成本
- 人工决策: 确认根目录采用“英文 `README.md` + 中文 `README.zh-CN.md` + 顶部双向链接”的布局

## 2. 有效做法

- 保持 `README.md` 作为英文主入口，同时新增单独的中文版本，比中英混排在一个文件里更清晰
- 在两份 README 顶部直接放语言切换链接，能让根目录入口非常明确
- 沿用现有 install/update/vendor/override 的文案结构，避免双语版表达出两套不同的接入流程

## 3. 失败点

- 当前没有自动机制保证中英文 README 后续同步，后面如果只改一份，另一份可能滞后
- 根目录已有多份中文分析文档，之前容易让人误以为这些就是正式中文入口，说明 README 入口命名此前不够明确

## 4. 仓库特定经验

- 对 baton 这种同时服务中文和英文读者的仓库，根目录最好明确只有一份正式英文 README 和一份正式中文 README
- 其他根目录中文专题文档应继续作为补充材料，而不是承担 README 角色

## 5. Harness 经验

- 文档入口类需求也值得按 harness 流程做，因为它同样需要 scope、requirements、architecture 和验证闭环
- “默认中文”不等于“只保留中文版”；对外入口仍然适合保留英文主 README，再补中文副本

## 6. 可标准化候选

- 后续可以补一个轻量脚本，专门检查根目录 README 双向链接和关键章节是否同时存在
- 若未来 README 继续频繁演进，可以考虑把双语维护规则写进文档贡献约定
